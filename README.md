# Vococo Report Writer

由 [chjm-ai](https://github.com/chjm-ai) 独立维护的中文汇报写作 Skill，技能名为 `vococo-report-writer`。

把会议纪要、产品研究、方案分析和数据复盘整理成给上级看的汇报：**删掉不影响判断的内容，保住支撑判断的具体依据。** 不是只求短，也不是把所有限制都写进正文。

## 适用场景

- 根据已有材料重组产品报告、研究简报、方案提案与会议汇报。
- 压缩冗长草稿，保留判断、依据和适用条件。
- 将空壳标题改成带结论的标题，减少重复警示和工作过程自述。

不负责替代调研、联网查证或补造证据；不承诺通过 AI 检测器。

## 14 条汇报规则

| # | 规则 |
|---|---|
| 1 | 先讲业务价值和选择，再交代研究过程 |
| 2 | 判断保留具体依据，并解释业务含义 |
| 3 | 影响判断的限制就近说明，不反复提醒 |
| 4 | 材料缺证据，不改写成事情不存在 |
| 5 | 压缩时保留否定方向 |
| 6 | 不用重复的否定警示为段落收尾 |
| 7 | 核对清单与汇报正文分开 |
| 8 | 不添加免责声明和自述工作过程的套话 |
| 9 | 正式直接，不虚构感受和经历 |
| 10 | 不擅自加总、换算或推算新数字 |
| 11 | 不替材料补职务和身份 |
| 12 | 不提高态度强度，不将个人观察扩大成整体结论 |
| 13 | 保留偶发、样本和方法限定 |
| 14 | 各级标题尽量直接交代该节结论 |

事实、条件和确定程度优先于文风。完整约束见 [SKILL.md](SKILL.md)。

## 安装与使用

将本仓库克隆到你的 Agent 技能目录下，目录名使用 `vococo-report-writer`。如使用集中管理的共享技能库，应克隆到共享库，再沿用既有软链接，不直接改各工具的链接入口。

也可以将 `SKILL.md` 作为规则提供给支持文件读取的模型。

示例请求：

> 使用 vococo-report-writer，根据下面的材料重组一份给上级看的产品研究汇报。允许删重复、合并限制和调整顺序；保留影响判断的事实、数字与条件。只交付成稿。

## 测试与边界

- [tests/README.md](tests/README.md)：编辑边界和 Markdown 结构检查方法。
- [tests/round8_cases.md](tests/round8_cases.md)：汇报规则的人工核对清单。
- `tests/fixtures/round8/`：人工构造的测试材料，不是实际产品调研结论；其中的价格、调查、人物和观察只供测试语义保持，不可作为业务依据。

历史实验的完整输入、输出与评审记录未随本仓库发布，因此本 README 不将历史分数或胜率作为可复现的效果证明。结构脚本也不能验证事实和判断，需要人工复读，并用未参与规则提炼的新材料继续测试。
