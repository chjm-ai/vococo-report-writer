# humanizer-zh-reports：中文上级汇报写作 Skill

给 Agent 用的写作规则集：把会议纪要、调研材料、数据复盘改写成「给上级看的汇报稿」——开头先说结论，判断有事实撑着，限制只出现一次，标题本身带结论。

它是在 [Humanizer-zh](https://github.com/op7418/Humanizer-zh)（作者 歸藏，MIT）基础上做的本地扩展。通用润色能力沿用上游；本仓库新增的是「本地定制：上级汇报」一节和配套测试素材。

## 它解决什么问题

普通的中文润色会把汇报写成两样东西：

- **防御体**：每段结尾都补一句「不能认定」「不等于」「尚待验证」，读的人拿不到判断。
- **空壳体**：标题写「会议情况」「问题分析」「下一步」，正文罗列过程，读者要读完才知道结论。

这套规则把两类问题都改成行为规则：不按禁词表判，按「这句话是不是在防止误解、是不是把未知写成了否定」判。

## 规则概览

**写作（1–9）**

| # | 规则 |
|---|---|
| 1 | 业务先行：先说是什么、对业务价值在哪、建议怎么选 |
| 2 | 判断由事实撑着，主要判断后面说清对业务意味着什么 |
| 3 | 限制就近、一次说完，段末只为防误解的一句话删掉 |
| 4 | 不替材料下结论，缺证据就说「材料未披露」或直接说缺什么 |
| 5 | 否定方向原样保留 |
| 6 | 不用否定句收尾 |
| 7 | 检查与正文分开，只写影响读者判断的待核事项 |
| 8 | 不加免责声明和套话 |
| 9 | 正式直接，不加个人感受和虚构经历 |

**不得替材料做的事（10–13）**

| # | 规则 |
|---|---|
| 10 | 不自行加总、换算、推算 |
| 11 | 不补职务和身份 |
| 12 | 不提高态度强度 |
| 13 | 偶发不等于必然 |

**版式（14）**

| # | 规则 |
|---|---|
| 14 | 标题带结论：每级标题写成能独立读懂、带判断的句子 |

完整条文、例子和判断标准见 [SKILL.md](SKILL.md)。

## 实测效果

在 16 份真实中文材料 × 3 个模型（DeepSeek Flash / DeepSeek V4 Pro / Kimi K3.1 Pro）上对比新旧规则稿：

- 使用否定句收尾的篇数明显下降；
- 空壳标题：旧规则 43/45 篇存在，新规则 10/45 篇存在。

这些都是小样本，只说明规则有效，不证明它稳定。

## 安装

```bash
# Claude Code / 兼容 Agent 的 skills 目录
git clone https://github.com/chjm-ai/humanizer-zh-reports.git ~/.claude/skills/humanizer-zh-reports
```

或者把 `SKILL.md` 放进任意 Agent 的 skill / 规则目录。
